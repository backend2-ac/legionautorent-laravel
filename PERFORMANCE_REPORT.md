# Производительность LEGIONAUTORENT — Laravel

Измерено 8 октября 2026 через локальный production Docker/Nginx/PHP-FPM, Lighthouse 13.5.0, headless Chromium. Анимация включена: постер, манифест и прогрессивная canvas-последовательность. В режиме staging сторонняя аналитика отключена. Lighthouse измеряет загрузку, а плавность прокрутки проверяется отдельно браузером.

| --- | ---: | ---: | ---: | ---: | ---: |
| Мобильный | 97 | 2326.5 мс | 0 | 103 мс | 1327.8 мс |
| Мобильный, повтор | 96 | 2327.1 мс | 0 | 102.1 мс | 1285.8 мс |
| Компьютер | 100 | 621.8 мс | 0 | 0 мс | 350.3 мс |

Мобильный результат 96–97, компьютер 100. До доработки Laravel было 95/100; утверждённый старый Django-отчёт показывал 97/100. Целевые 98–99 пока не достигнуты. Повторный мобильный замер показывает обычную вариативность лабораторного измерения; оба результата включены. Проверка на PS.kz с реальной сетью и включённым GTM ещё необходима. Полевого INP в локальной среде нет: TBT указан как лабораторная метрика, не как INP.

У общих контактов/меню/текстов общий кеш с обновлением после сохранения и транзакции. Нельзя публично кешировать HTML с персональными сессиями, nonce и токенами форм. Runtime Docker хранится в отдельном Linux-томе на D; Nginx отдаёт статические файлы, gzip и долгий кеш версионированных ресурсов.

Нет горизонтального переполнения или JS-ошибок в проверенных сценариях.

WebKit-тест на Windows не заменяет физический iPhone/Safari. Настоящие iPhone/Android, изменение высоты адресной строки, реальные FPS/INP и медленные сети после размещения на PS.kz этим замером не подтверждены. Исходные 60 fps не гарантируют 60 fps отрисовки любого устройства.

## Совместимость анимации — 12 октября 2026

Исправлен воспроизведённый сбой запуска: браузер со старым API MediaQueryList останавливал главный JS на `addEventListener`, и анимация оставалась неподвижной. Теперь используется современный API, а при его отсутствии — `addListener`. Сборка также преобразует синтаксис для Safari 11.1, Chrome 64, Firefox 67 и Edge 79; это цели компиляции, а не подтверждение испытаний каждой старой версии браузера.

При отсутствии WebP выбирается отдельная JPEG-последовательность: 596 кадров, 768×432, 75 пакетов, 13 983 320 байт. Обычные браузеры продолжают получать прежние WebP-наборы; JPEG дополнительно не скачивается. Мастер и WebP-кадры не изменены. JPEG-постеры служат запасным вариантом для `<picture>`, сохраняя настоящий HTML-заголовок и локализованный alt.

Воспроизведение JPEG-набора из утверждённых мобильных WebP-пакетов (PHP GD с WebP/JPEG):

```sh
php artisan hero:build-jpeg --quality=80 --no-interaction
npm run build
```

Worker и createImageBitmap имеют ограниченное время ожидания и запасной декодер через Image. Отсутствие IntersectionObserver, ResizeObserver, AbortController и новых viewport-единиц не останавливает страницу. Если canvas, JS-модуль или загрузка кадров недоступны, остаётся статичный постер с работающими ссылками и каталогом. При prefers-reduced-motion статичный вариант включается намеренно.

Мобильная высота фиксируется до первого отображения; изменение видимой области корректирует положение кнопок, сохраняя высоту анимации. Декодирование начального буфера начинается после готовности постера и двух кадров браузера, чтобы дать первому экрану приоритет.

Проверены 33 сценария совместимости в Chromium, WebKit и Firefox: полный оборот и обратная прокрутка, старый MediaQueryList, отсутствие современных API и WebP, зависший worker/bitmap, недоступный canvas, ошибка загрузки кадров или JS, reduced-motion и отключённый JS. Ещё 23 проверки охватывают мобильные ширины 320–525 px, горизонтальный экран, desktop, кнопки и баннеры городов. Проверки имитируют ограничения браузеров; физические iPhone/Android и встроенные браузеры Instagram/Telegram отдельно не испытаны.

Свежий мобильный Lighthouse на локальном production Docker после исправления: **97/100, LCP 2402.4 мс, CLS 0, TBT 62 мс, FCP 1239.0 мс**. Lighthouse 13.5.0, стандартная симуляция Moto G Power, `--disable-storage-reset`, без параллельного браузерного теста. Предварительный замер обнаружил задержку отображения постера (LCP 3578.7 мс); после переноса подготовки кадров за декодирование постера она устранена. Значения выше от 8 октября сохранены как исторические, прямое сравнение разных запусков не является полевым измерением.

Полные локальные результаты: `output/hero-compatibility/`, исключённый из Git. Краткий отчёт: `reports/hero-compatibility.json`. PHP-проверки целостности JPEG-пакетов, постеров и переводов: 9 тестов, 2196 утверждений; успешная production-сборка Docker обязательна для этой версии.

После финальной сборки Docker также прошли 6 проверок ранней прокрутки/перехода к каталогу и 9 повторных проверок полного оборота: обычный запуск, отсутствие новых API и JPEG-вариант в каждом из трёх движков.

## Полноэкранная версия — 13 октября 2026

На горизонтальных экранах шоурум заполняет весь первый экран (`object-fit: cover`). На вертикальных экранах сохранён весь автомобиль (`contain`) на полноэкранном тёмном фоне. Мобильная высота закрепляется при открытии и не меняется при сворачивании адресной строки. Заголовки и ссылки остаются HTML.

Добавлен набор **Full HD 1920×1080: 596 кадров, 75 пакетов, 26 197 818 байт**, WebP quality 86. Это исходное разрешение утверждённого мастера, без апскейла и генерации новых деталей. Full HD постер: 29 044 байта. Мобильный постер остался 6 016 байт. Мастер, мобильные и 720p кадры сохранены без изменений.

Вариант выбирается по размеру показываемого изображения и плотности пикселей (DPR учитывается максимум до 2): 768×432 — 6 493 780 байт, 1280×720 — 13 688 314 байт, 1920×1080 — 26 197 818 байт. Одновременно загружается только выбранный вариант. Save-Data ограничивает выбор мобильным или 720p набором; без WebP применяется прежний JPEG. Полный вес набора не равен весу первого экрана: до прокрутки загружаются максимум четыре пакета, далее — нужные кадры и ближайший буфер. Удалены прежние preload пакетов, которые могли дополнительно скачать неподходящее разрешение. Приоритет у постера. Декодированный кеш ограничен примерно 96 MiB пиксельных данных; прочие расходы браузера в это число не входят.

Воспроизведение Full HD из `public/static/hero/hero-60fps.mp4`:

```sh
php artisan hero:build-fullhd --quality=86 --no-interaction
npm run build
```

Команда использует ffmpeg из `FFMPEG_PATH` (или параметра `--ffmpeg`). Выполненная команда извлечения:

```sh
ffmpeg -hide_banner -loglevel error -y \
  -i public/static/hero/hero-60fps.mp4 -map 0:v:0 -an \
  -vf setsar=1 -fps_mode passthrough -c:v libwebp \
  -quality 86 -compression_level 5 -start_number 0 TEMP/%04d.webp
```

`TEMP` — автоматически создаваемая временная папка внутри `storage/app`. Команда проверяет SHA-256 мастера, сохраняет все 596 кадров, объединяет их по 8 в пакеты с длинами uint32 LE, создаёт WebP/JPEG постеры и обновляет `sequence.json`. Имена пакетов включают хеш содержимого. После упаковки временные изображения удаляются.

Проверены 29 сценариев полноэкранной версии: 18 сочетаний браузера, размера и DPR в Chromium/WebKit/Firefox, 9 проверок хлебных крошек RU/KZ/EN и 2 входа в `/admin/`. Размеры: 1440×900, 1920×1080, 390×844, 320×568, 844×390, 820×1180. Проверены полный оборот и обратная прокрутка, отсутствие горизонтального переполнения, положение кнопок и стабильная мобильная высота. В Chromium события касания с последующим отпусканием дали прокрутку 325 → 399 px по инерции; кадры продолжили обновляться. Первоначальный `synthesizeScrollGesture` не прокрутил эмулируемую страницу; проверка повторена через `dispatchTouchEvent`, оба протокола сохранены.

Админка теперь `/admin/`; старые `/control-legion/...` перенаправляются на соответствующий экран. Вход и авторизованное редактирование проверены браузером. Хлебные крошки читаемы на мобильном; главная города обозначена одним текущим пунктом, а ссылки с внутренних страниц сохраняют выбранный город. Админка исключена из индексации заголовком X-Robots-Tag. Прошли целевые PHP-тесты (22 разных теста; 13 из них повторно после исправления middleware), Pint, Vite и production-сборка Docker. Данные локальной MySQL сохранены.

Полные локальные протоколы и снимки: `output/fullscreen-release/`. Физические iPhone/Android и браузеры внутри приложений отдельно не испытаны; эмуляция размеров и API не подтверждает работу каждого устройства. 1080p-источник не гарантирует детализацию нативного 4K, а 60 fps исходника — 60 fps отрисовки на любом телефоне.

## Исправление загрузки на реальной сети — 13 октября 2026

Проверка опубликованного сайта обнаружила проблему, которую предыдущие локальные проверки не выявили: при непрерывной прокрутке загрузчик запрашивал новые HD-кадры быстрее, чем сеть доставляла их. На 5 Мбит/с автомобиль мог оставаться на постере весь десятисекундный проход. На обычном соединении два зависших запроса занимали оба слота загрузки до 15 секунд.

Добавлена временная облегчённая последовательность: **120 кадров 640×360, WebP quality 65, 832 428 байт**. Четыре пакета покрывают весь поворот с постепенно возрастающей плотностью кадров. Уже первый пакет (**213 108 байт, 31 кадр**, включая начало и конец) позволяет прокручивать весь оборот. JPEG-вариант для браузеров без WebP: 1 899 123 байта; он не скачивается в браузерах с WebP.

Постер по-прежнему отображается настоящим HTML-изображением до запуска загрузки. Если точный кадр ещё не приехал, canvas показывает ближайший кадр облегчённой последовательности. Чёткие кадры исходных 768×432 / 1280×720 / 1920×1080 наборов догружаются около текущего положения. При остановке кадр заменяется оригинальным по разрешению. На слабой сети временная картинка менее детальная и частота смены кадров ниже; одинаковые 60 fps на любом соединении не гарантируются. Исходник и существующие HD-пакеты не изменены.

Устаревшие задания удаляются из очереди. Ошибочные запросы повторяются с ограничением частоты. Таймаут HD подстраивается под измеренную скорость загрузки preview (4–20 секунд), поэтому медленная передача не перезапускается бесконечно. Два зависших HD-запроса не блокируют уже загруженную последовательность. Кэш decoded preview ограничен 16 изображениями; HD-кэш — примерно 76 MiB пиксельных данных. Основной и запасной декодеры сохранены.

Добавлены Cache-Control и корректный MIME для пакетов в Apache `.htaccess`; долгий immutable-кэш применяется только к именам с хешем. При раздаче файлов напрямую nginx настройки `.htaccess` не действуют: нужно применять серверный конфиг. Сам загрузчик повторно использует HTTP-кэш (`force-cache`), а новые preview-пакеты имеют уникальные адреса по содержимому.

Воспроизведение ассетов (ffmpeg и PHP GD с JPEG/WebP):

```sh
php artisan hero:build-preview --no-interaction
npm run build
```

Точная команда ffmpeg для утверждённого мастера с 596 кадрами:

```sh
ffmpeg -hide_banner -loglevel error -y \
  -i public/static/hero/hero-60fps.mp4 -map 0:v:0 -an \
  -vf "select='not(mod(n,5))+eq(n,595)',scale=640:-2:flags=lanczos,setsar=1" \
  -fps_mode vfr -c:v libwebp -quality 65 -compression_level 6 \
  -start_number 0 TEMP/%04d.webp
```

Artisan проверяет SHA-256 мастера, упаковывает выбранные кадры в четыре пакета с индексами исходных кадров и хешами, создаёт JPEG через GD quality 75 и обновляет `sequence.json`. `TEMP` находится в `storage/app` и очищается после сборки.

Регрессионная проверка непрерывной прокрутки: `tests/browser/hero_network.py` (Python + Playwright). Переменная `HERO_BASE_URL` выбирает сайт; по умолчанию локальный Docker на 8004. `HERO_PROFILES` позволяет выбрать `desktop`, `mobile`, `mobile-5mbps`, `desktop-5mbps`, `mobile-512kbps`, `two-stalled-hd`, `preview-unavailable`, `midpoint-cold`. `BROWSER_EXECUTABLE` задаёт путь к Chromium; `HERO_REPORT` — папку результатов. Скрипт проверяет движение вперёд и назад, длительность остановок, точные конечные кадры и возвращение полного разрешения. Это лабораторная проверка браузеров, а не измерение на физических iPhone/Android.
